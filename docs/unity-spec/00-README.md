# Frog Cart Puzzle — спецификация для реализации в Unity

Это полный набор документов для того, чтобы агент (Claude) в Unity собрал играбельный
прототип с нуля, без обращения к HTML-исходнику. Все числа — итоговые, из работающего
прототипа `Frog Cart Puzzle.dc.html`.

## Порядок чтения
1. `01-layout.md` — экран, координаты, геометрия рельсового контура.
2. `02-art.md` — палитра, материалы, все размеры и стили объектов.
3. `03-level-data.md` — данные уровня, вагонетки, очередь, ёмкости.
4. `04-gameplay.md` — правила, состояния, ввод, победа/поражение.
5. `05-feel-anim.md` — тайминги, кривые, тактильная отдача, язык движения.
6. `06-unity-implementation.md` — сцена, префабы, классы C#, готовый код математики.
7. `07-checklist.md` — приёмочный чек-лист.

## Что это за игра (в одном абзаце)
Портретный казуальный пазл 390×844. Картинка собрана из крупных цветных блоков в сетке
14×16. Вокруг картинки по замкнутому деревянному рельсовому контуру медленно катятся
вагонетки; в каждой сидит жаба своего цвета, на борту — число (сколько блоков она ещё
может съесть). Игрок тапает по блоку — ближайшая жаба нужного цвета выстреливает языком,
выдёргивает блок и съедает его. Задача — очистить всю картинку, пока не кончились жабы.

## Ключевые ограничения
- Портрет, референс-разрешение **390×844** (логические пиксели = единицы UI).
- Никакого текста, кроме HUD (номер уровня, процент) и чисел на вагонетках.
- Мышь и тач работают одинаково (Pointer/Touch через один код).
- Стиль: глянцевый casual-3D, имитированный в 2D: пухлые округлые формы, один мягкий
  блик, контактная тень под каждым объектом, тёплый деревянный фон. Ничего плоского,
  никаких размытых градиентных «дымок».
- Никакой анимации длиннее **0.3 c** (кроме падения конфетти и покачивания панели).
