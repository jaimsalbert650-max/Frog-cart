# Game Settings

Веб-редактор `Config.asset` — всех 27 чисел, которыми настраивается ощущение
игры. Один файл `index.html`, без сборки и без сервера: открываешь в Chrome или
Edge, выбираешь папку `Assets/Game/Data`, крутишь ползунки, `Ctrl+S`.

Тот же подход, что и у `tools/level-editor`: преамбула `.asset` копируется как
есть, числа пишутся тем же способом, что и Unity. Открыть и сохранить, ничего не
поменяв, даёт пустой diff.

**Auto** рядом с кнопкой сохранения — писать на диск самому, без `Ctrl+S`. Запись
отложена на 0.6 с после последней правки, поэтому протаскивание ползунка даёт одну
запись в конце, а не сотню по дороге. При уходе с вкладки (переключился в Unity)
запись происходит сразу. Галочка запоминается.

Учти: с включённым Auto каждая правка сразу в файле. `Ctrl+Z` в редакторе работает
как раньше, но «покрутил и закрыл без сохранения» больше нет — для этого
`git checkout Assets/Game/Data/Config.asset` или выключить Auto.

## Что видно, кроме ползунков

Каждое поле подписано тем, что про него сказано в `GameConfig.cs` — включая
причины, по которым границы именно такие. Изменённые поля подсвечены жёлтым, у
каждого своя кнопка возврата к заводскому значению, слева в оглавлении видно,
в какой группе что тронуто.

Справа — то, во что настройки превращаются на самом деле. Ничего декоративного,
каждое число повторяет конкретную строку рантайма:

| Показ | Откуда |
|---|---|
| Периметр контура, время круга | `LoopPath` — 1758 единиц; при `railSpeed` 64 круг за 27.5 с |
| Радиус досягаемости против центра картинки | центр отстоит от ближней нитки рельса ровно на 180 — отсюда нижняя граница `biteRange` |
| Пауза между укусами | `GameController.BiteInterval` = `tongueOut + tongueBack + 0.05` |
| Полоса выигрыша | `WinSequence`: `winDelay`, затем силуэт, затем `max(0, winPanelDelay − winSilhouette)` |
| Кривые затухания | `Decay(...)`, время до 1% = `ln 100 / rate` |

## Проверки

Внизу справа — то, что стоит поймать до запуска:

- значение вне `[Range]` из C# (Unity всё равно обрежет его при загрузке);
- `biteRange` меньше 180 — центр картинки недостижим, уровень встанет;
- `railSpeed` 0 — вагонетки не едут;
- **`winPanelDelay` не больше `winSilhouette`** — тогда он не делает ничего.
  Это не выдумка: на заводских числах 1.1 против 1.2, и панель появляется просто
  по концу силуэта. Настройка уже сейчас мёртвая.

## Числа живут в спеке

`GameConfig.cs` начинается с того, что ни одно число не придумано: меняется
число — меняется и `docs/unity-spec`. Веб-редактор пишет только `.asset`, поэтому
кнопка **Copy as C#** отдаёт готовые строки инициализаторов со всеми
`[Range]` — чтобы настроенное вернулось в исходник и в спеку, а не осталось
только в ассете.

Пересборка ассетов больше не трогает `Config.asset`: `FrogCartSetup.CreateConfig`
создаёт его, только если файла нет. Вернуть заводские числа — удалить файл и
запустить **Frog Cart → Rebuild Assets And Scene**.

## Тесты

Кнопка **Self-test** — 20 проверок в браузере: round-trip формата, типы полей
(bool пишется как `0`/`1`, int без дробной части), запись отсутствующего поля,
сохранение неизвестных ключей, геометрия контура, все производные числа.

Отдельно прогнано против исходников проекта: все 27 полей `GameConfig.cs` на
месте и ни одного лишнего, каждое значение по умолчанию совпадает с
инициализатором в C#, все пять атрибутов `[Range]` совпадают, реальный
`Config.asset` возвращается байт в байт.
