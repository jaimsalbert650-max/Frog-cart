# 03. Данные уровня

## Формат
Уровень — массив из 16 строк по 14 символов. Цифра = индекс цвета (`0` — пусто).
Хранить как `string[]` в ScriptableObject `LevelData` (плюс поля вагонеток и очереди),
чтобы уровни менялись без правки кода.

## Уровень 1 — воздушный шар
```
"00000055000000"   // 0  синий флажок на верхушке
"00000322300000"   // 1
"00034322343000"   // 2
"00234322343200"   // 3
"00234322343200"   // 4
"00234322343200"   // 5
"00234322343200"   // 6
"00034322343000"   // 7
"00004322340000"   // 8
"00000322300000"   // 9
"00000022000000"   // 10 «горловина»
"00000100100000"   // 11 стропы
"00000111100000"   // 12 корзина
"00000111100000"   // 13
"00000111100000"   // 14
"00000000000000"   // 15
```
Вертикальные «клинья» оболочки заданы цветом столбца (2..11):
`r, o, y, o, r, r, o, y, o, r` — красный по краям, оранжевые клинья, жёлтые «блики».
Корзина и стропы — цвет 1 (тёмный, читается как коричнево-чёрный).

**Столбцы 0–1 и 12–13, а также ряд 15 всегда пустые** — по ним проезжают жабы боковых и
нижних вагонеток и не должны заслонять блоки.

## Баланс
Суммарная ёмкость по цвету ≥ числа блоков: black 19≥14, red 32≥28, orange 58≥30,
yellow 30≥14, blue 2=2 (в притык — самый «напряжённый» цвет).
Уровень 1 проходим всегда; проигрыш здесь недостижим по построению — это правильно
для первого уровня, но механика проигрыша обязана работать (проверяется тестовым уровнем,
где ёмкости заведомо меньше — см. `07-checklist.md`).
